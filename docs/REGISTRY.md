# The `.actlith` registry

`.actlith` at the repository root is the one file you write. actlith reads
it, and nothing else, to decide which workflows exist and what goes into
them; `actlith gen` renders it, and `actlith check` holds the repository
to it. The same file with the same actlith version always renders the
same bytes: no clock, hostname or network goes into the output.

`actlith seed --init` writes a first one from what your repository already
has. After that it is yours: actlith never rewrites it, except `actlith
pin`, which rewrites only its `## actions` section.

## Shape

```text
format 1

# A comment line starts with `#`.

## workflows
id|kind|systems|cache|args
ci|gate|-|my-cache|-
build|build|x86_64-linux,aarch64-darwin|my-cache|package=hk,timeout=60

## actions
action|version|sha
actions/checkout|v7.0.1|3d3c42e5aac5ba805825da76410c181273ba90b1

## hand-written
path|reason
.github/workflows/release.yml|publishes to crates.io; no kind for it yet

## bots
bot|args
coderabbit|central=my-org/coderabbit

## runners
system|labels
x86_64-darwin|self-hosted, macOS, X64
```

- The first line is `format 1`. A file with a newer format is refused, so
  an old actlith never misreads a new file.
- Each section starts with `## <name>` and a header row, then one row per
  line, cells split on `|`.
- `-` is an empty cell. `\|` is a literal pipe inside a cell.
- Lines starting with `#` are comments, anywhere.
- A bad row stops everything (exit 2) with the line number and the fix:

  ```text
  .actlith:5: kind `gate` has no arg `bogus`
    fix: remove `bogus` or use one of: command, timeout
  ```

## `## workflows`

One row per generated workflow, written to `.github/workflows/<id>.yml`.

| column | meaning |
| --- | --- |
| `id` | the file name and the workflow's `name` |
| `kind` | `gate`, `build`, `update-pins` or `upstream`; see [KINDS.md](KINDS.md) |
| `systems` | nix systems, comma-separated; `-` = the kind's default |
| `cache` | a cachix cache name; `-` = no cachix steps |
| `args` | `key=value` pairs, comma-separated, checked against the kind |

Systems map to GitHub runners:

| system | runner |
| --- | --- |
| `x86_64-linux` | `ubuntu-latest` |
| `aarch64-linux` | `ubuntu-24.04-arm` |
| `aarch64-darwin` | `macos-latest` |
| `x86_64-darwin` | `macos-15-intel`, GitHub's last Intel image, available until August 2027 |

A `## runners` row puts a system on your own runner instead (below).

An unknown kind, arg or system is an error, never ignored. Args and
systems split on `,`, so an arg value cannot hold a comma. Every kind
takes `timeout` (job minutes, default 30); the rest are listed per kind in
[KINDS.md](KINDS.md).

With a `cache`, the workflow reads the `CACHIX_AUTH_TOKEN` secret to push;
pull requests from forks get no secrets, so they read from the cache and
skip the push. `actlith report` lists every secret each workflow reads.

## `## actions`

Optional. actlith ships a table of the actions its kinds use, each pinned
to a commit SHA. A row here overrides one entry: the generated workflows
use your SHA, with the version as a comment. `actlith pin` fills this
section from the GitHub API (through `gh`), and `actlith pin --dry-run`
prints the rows without writing them.

## `## hand-written`

Workflows actlith does not generate, each with the reason. `actlith check`
fails on a file in `.github/workflows/` that is neither generated by a row
nor listed here, on a listed path that does not exist, and on a path both
listed and generated. A reason is required, so the exceptions stay
deliberate.

## `## bots`

Configuration files for review and supply-chain bots. actlith writes the
files; installing each bot's GitHub App is your step, and
`actlith report` lists the apps your rows assume.

| bot | writes | args |
| --- | --- | --- |
| `coderabbit` | `.coderabbit.yaml`, a stub pointing at a central config repository | `central=<owner>/<repo>` |
| `greptile` | `greptile.json`, skipping release PRs | - |
| `socket` | `socket.yml` | - |

As with workflows, `actlith check` reports a bot file that no row backs.
[SERVICES.md](SERVICES.md) lists the services considered, with their
free-tier terms.

## `## runners`

Your own runners, by nix system. The section is optional and reads the
same in lablith's file.

| column | meaning |
| --- | --- |
| `system` | a nix system, once per section |
| `labels` | the runner's labels, comma-separated, at least one; each is letters, digits, `.`, `_` and `-`, not starting with `-` |

Every row's jobs for that system run on `runs-on: [<labels>]`, in a job
of their own (`gate-<system>`, `build-<system>`), and only for a push, a
schedule, a manual run or a pull request from this repository: never for
a fork's pull request, which would run a stranger's code on your machine.
There is no switch to turn that off; [KINDS.md](KINDS.md#own-runners)
has the details. A system without a row runs on the hosted runner in the
table above.
