# Workflow kinds

Catalogue of the workflow templates (kinds) actlith ships in v1. Read it
together with SPEC-PROMPT.md. Every kind here is in scope for building;
nothing in this file is deferred.

Shapes come from the fleet survey of 2026-10-15: pklith `ci.yml` for `gate`,
nix-hk `build.yml`, `update-pins.yml` and `upstream.yml` for the others.

## Common to every kind

- Header: `# generated by actlith gen from .actlith; do not edit`.
- `permissions: contents: read` at top level; jobs widen only what they need.
- `concurrency`: group `<id>-${{ github.ref }}`; cancel in progress for
  push / pull request kinds, never for scheduled kinds (a cancelled bump
  run can leave a half-pushed branch).
- `timeout-minutes` on every job (default 30).
- Checkout pinned by SHA, `persist-credentials: false` unless the job pushes.
- install-nix pinned by SHA, with `extra-substituters` and
  `extra-trusted-public-keys` for the row's cache.
- Every `run:` is one line. Logic longer than one command lives in a script
  seeded into the repository (`scripts/actlith/<name>.sh`, see
  SPEC-PROMPT.md), so shellcheck, bats and xenolith see it.

## Row values

`.actlith` `## workflows` columns: `id|kind|systems|cache|args`.

- `id`: file name `.github/workflows/<id>.yml`, and the workflow `name`.
- `kind`: one of the kinds below, or a kind the repository adds.
- `systems`: nix systems, comma-separated; `-` = the kind's default.
- `cache`: cachix cache name; `-` = no cachix steps.
- `args`: `key=value` pairs, comma-separated, validated per kind; an unknown
  key is an error, not ignored.

## `gate`

The hk gate on every supported system. Replaces the fleet `ci.yml`.

- Triggers: push to `main`, `pull_request`, `workflow_dispatch`.
- Job `gate` (name is stable: `pklith protect` reads it), matrix over systems,
  `fail-fast: false`.
- Steps: checkout (`fetch-depth: 0`, the semver step needs tags), install-nix,
  cachix (push skipped for fork PRs, `pushFilter` keeps sources out), run the
  gate command.
- Default systems: `x86_64-linux`, `aarch64-linux`, `aarch64-darwin`.
- args: `command` (default `nix develop --command hk check --all --check`),
  `timeout` (minutes).

## `build`

Build and cache a flake package on every system, then prove the cache has it.
For packaging repositories such as nix-hk.

- Triggers: as `gate`.
- Job `build`: matrix over systems, `nix build --print-build-logs
  .#packages.<system>.<package>`; cachix push only from `main`.
- Job `check`: `nix flake check --all-systems`, then eval-only for systems
  without a runner (`x86_64-darwin`), so they cannot rot silently.
- Job `verify-cache` (needs `build`, `main` push only): every system's output
  path answers 200 from the cache. Reason: a cachix push failure does not fail
  its job.
- args: `package` (required), `timeout`.

## `update-pins`

Follow `nixpkgs-lock` and propose the bump as a PR. Pull model: the consumer
polls; nixpkgs-lock holds no cross-repo token.

- Triggers: `schedule` (cron from args), `workflow_dispatch`.
- Job permissions: `contents: write`, `pull-requests: write`.
- Steps: checkout (credentials kept, it pushes), install-nix, seeded script
  `update-pins.sh`: update the input, build, push a branch
  `pins/nixpkgs-<short rev>`, open a PR; idempotent if the branch exists.
- Also runs `actlith pin` and `actlith gen` in the same branch, so action pins
  and a new actlith version arrive through the same reviewed PR.
- args: `cron` (default `50 6 * * *`, after nixpkgs-lock refreshes), `build`
  (flake attribute built before proposing; default `.#default`).
- Known limit: a PR opened with `GITHUB_TOKEN` does not trigger other
  workflows, so the gate does not run on it until someone pushes or reruns.
  args `token` names a secret with a GitHub App or fine-grained token to lift
  this; default is `GITHUB_TOKEN` and the limit is documented.

## `upstream`

Poll an upstream release and propose the bump as a PR. Same pull model and
PR mechanics as `update-pins`.

- Triggers: `schedule` (cron from args), `workflow_dispatch`.
- Steps: checkout, install-nix, cachix read-only, the repository's own bump
  script (path from args; it prints `NEW_VERSION=` to `GITHUB_OUTPUT`), then
  the seeded `open-pr.sh`.
- args: `script` (required), `cron` (default `20 6 * * *`), `branch-prefix`
  (default `upstream/`), `token` (as in `update-pins`).

## Not in v1

Survey one-offs (`release.yml` in 3 non-fleet repos, `format-upstream.yml`,
`publish-image.yml`, ...) stay hand-written and listed in `.actlith`
`## hand-written`. A kind is added only when two fleet repositories need it.
